# arc

## Оставшаяся функциональная и не функциональная часть для приложения

### Содержание

1. Доделать админку
2. Авторизация в панели администрирования
3. Оформление заказа
4. Связать каталог с бд
5. Добавить индексы в БД
6. Оптимизировать запросы

##### 1. Доделать админку

###### Ожидаем: На главной странице администратор должен видить статистику по общему количеству заказов и товаров, можно выводить данные в зависимости от выбранного периода.

###### Функциональные требования: Добавить новые методы для получения нужной информации с БД.

##### 2. Авторизация в панели администрирования

###### Ожидаем: пользователь вводит логин и пароль в форму и входит в систему.

###### Функциональные требования: На данном этапе будет только одна роль, _Администратор_. Ему будет доступен весь функционал в админке. Если в дальнейщем будет необходимость в каких то еще ролях, то по хорошему нужно добавлять _пермишены_ и уже ограничивать админку на базе существования у роли конкретного _пермишена_.

###### не функциональные требования: Пользователь будет заводиться в базе при миграции. В регистрации нет необходимости. (можем обсудить)

##### 3. Оформление заказа

###### Ожидаем: После добавления товаров в корзину пользователь должен оформить заказ.

###### Функциональные требования: Реализовать функцимонал что бы при офрмлении заказа, администратор получал заказ в своего бота, так же в админке должен быть функционал по управлению с заказом. При изменении статуса зказа, администратором, пользователь должен получать уведомления в предпочтительный тип связи

##### 4. Связать каталог с бд

###### Ожидаем: Клиент должен видить на сайте актуальные товары которые были добавлены в БД админом, а не моки.

###### Функциональные требования: Пройтись по всем компонентам и подготовить их к SSG либо к ISR (думаю, тут ISR лучше подойдет).

###### не функциональные требования: Нужно учесть SEO

##### 5. Добавить индексы в БД

###### Ожидаем: Пользователь / Администратор не должны фиксировать долгое одижание выполнения запросов, все запросы должны отрабатывать в пределах ожидания.

###### Функциональные требования: Необходимо проставить индексы для полей которые могут тормозить базу.

##### 6. Оптимизировать запросы

###### Функциональные требования: просто делаем.

##### 7. Добавить валидацию изображений

###### Функциональные требования: Реализовать валидацию по количеству изображений (5) в форме создания/редактирования product option
